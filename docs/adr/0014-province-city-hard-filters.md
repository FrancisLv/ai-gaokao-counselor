# 0014 · 省份与城市分别建模为地域硬约束

- 状态：已接受
- 决策者：Francis

报告后的明确地域否定必须形成画像硬约束并创建不可变 `REVISE_PLAN`。
“我不想去广东上大学”表示排除院校所在省份为广东的全部高校，而不是把“广东”
塞进城市字段或展开成一份可能不完整的固定城市清单。因此画像分别维护
`required_provinces / excluded_provinces` 与 `required_cities / excluded_cities`；
“广东”修改省份约束，“广州”修改城市约束，旧报告保持不变。

## 后果

- 新字段通过 additive proto 编号加入画像契约，并随 `profile_version` 固化。
- 算法在校验选科和估算概率前应用省份硬约束；排除省份后，属于该省的软城市偏好和
  冲突的城市硬约束会从修订画像中移除。
- 只对明确省份或城市执行硬约束；“华南”“南方”等无法唯一映射的大区表达先澄清。
- LLM 兜底只能提出相同的受限省份 patch，最终仍由服务端校验并重新确认画像。

## 2026-11-21 修订：大区表达与快捷组

大区表达在首次画像采集和报告后修订中使用同一套澄清规则。系统可提供 release 绑定的
“东北”“华北”“西北”等大区快捷组，但快捷组只辅助填写省份多选，必须展示其包含的
具体省份；用户确认后画像只固化为受控省份集合，不保存“北方”或快捷组身份，也不提供
未经确认的一键硬筛。

用户未给出省份或未明确取消该限制时，不进入候选生成或创建新的 `REVISE_PLAN`。
系统只进行一次针对性澄清；用户明确表示“先不管这个限制”后，才可生成或修订不含该
硬约束的方案。用户已表达的地域排除意愿不得被静默忽略。
