# 0008 · 对话消息服务端持久化，报告后筛选创建修订 run

- 状态：已接受（2026-11-20）
- 决策者：Francis

`session` 是对话容器，用户可见消息写入 `chat_message` 并按 `principal` 授权读取；
报告生成后，解释请求绑定当前 `result_version` 创建 `EXPLAIN_RESULT` run，筛选或约束
变化创建带父结果引用的 `REVISE_PLAN` run。旧报告保持不可变，新方案重新确认画像并
经过完整资格、算法、验证和发布门禁。

这样选择是因为“最近对话”必须跨浏览器恢复，且不同设备不能各自维护一份事实；
同时筛选条件会改变候选身份、概率与资格结论，不能由模型直接编辑静态报告。代价是
每次有效筛选都要重新运行确认与计算，并新增消息表、会话查询接口和结果版本时间线。
如果未来只修改软偏好且已有可靠依赖追踪与回归，可单独优化为同 release 增量执行，
但不得复用旧概率或跳过正式结果门禁。
