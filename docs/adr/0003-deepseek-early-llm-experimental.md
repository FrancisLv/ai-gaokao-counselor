# 0003 · 早期实验链路采用 DeepSeek，M5 收口 llmgw 网关

- 状态：已接受（2026-11-18）
- 决策者：Francis
- 关联：`gap-analysis.md §6` 决策3、PRD 风险#3 / §8、`internal/llmgw/`

## 背景

PRD 已定 LLM 调用路径分阶段：早期里程碑允许 Python 直连模型快速验证（显式标注「无完整治理的实验链路」），M5·E 收口为 llmgw 网关前置闸门。但用哪家模型 / 供应商未定。M2 任务底座的退出条件明确「用测试替身即可，不需真实付费模型」。

## 决策

- **M2**：用测试替身（mock），不接真实模型；
- **M3 起的早期实验链路**：采用 DeepSeek（模型 id `deepseek-v4-pro`），Python 直连，显式标注为实验链路；
- **M5·E**：收口到 svc-llm-gateway 网关，统一路由 / 缓存 / 预算治理；
- 模型 id 在接线时对齐 DeepSeek 官方 API 文档确认；key 只放 `.env` / secrets，不入 Git，仅存在于 llmgw 侧。

## 理由 / 权衡

- DeepSeek 国产、国内直连无需代理、成本低（符合 PRD §7.2 降本方向）；
- 早期直连加快验证，但必须标注「无完整治理」，不作为正式保障；
- 接真实付费流量前，最低预算预占 / 隐私脱敏 / 调用账本治理须前置（不因里程碑顺序延后）。

## 被否决的备选

- OpenAI / Claude（国内需代理、成本高）；
- 全程测试替身到 M5（真实链路验证推迟）；
- 本地开源模型（编排容器仅 4GB 内存，跑本地大模型吃力）。

## 影响

- M3 起需配置 DeepSeek 直连客户端与 `.env` key；
- M5 收口时把直连替换为 llmgw 调用，模型档位按 role 路由；
- `deepseek-v4-pro` 的确切 id 与价格以接线时 DeepSeek 文档为准。
