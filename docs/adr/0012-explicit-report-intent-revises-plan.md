# 0012 · 明确筛选指令直接创建报告修订，LLM 仅作受限兜底

- 状态：已接受
- 决策者：Francis

报告后有正式结果时，城市、专业、层次、院校和风险偏好等明确筛选表达直接创建
`REVISE_PLAN`，不再先问用户“解释还是重做”。“我不想去北京上大学”和
“我不想学物理学专业”都是明确画像变更；句尾的“呢？”不能覆盖前面的约束语义。

路由采用确定性规则优先：高置信表达直接形成受限画像 patch；规则无法判断时，才调用
LLM 输出 `EXPLAIN_RESULT / REVISE_PLAN / CLARIFY` 和结构化 patch。LLM 不能直接修改
画像、候选、概率或报告，服务端会重新校验字段、枚举、城市、学校层次、冲突和分数范围；
模型不可用或输出越界时安全回退为澄清。

专业排除区分“名称精确匹配”和“关键词匹配”。“物理学专业”只排除名称完全等于
“物理学”的专业，不能顺带误删“应用物理学”“地球物理学”等专业；只有用户明确表达
“所有物理相关专业”时才使用关键词排除。

确认后的筛选仍创建新的 `REVISE_PLAN` run，重新确认画像并经过完整资格、算法、验证
和发布门禁。旧报告保持不变。LLM 兜底部署前必须在 release 中注册
`m5b_conversation_intent` prompt 和 `m5b_conversation_intent_v1` response schema，
并允许 `PRINCIPAL_DATA`；未配置时不影响确定性路由。

## 2026-11-21 修订：空 patch 的 LLM 兜底与增档门禁

deterministic 初步判断为 `REVISE_PLAN`、但实际没有产生画像 patch 时，也属于
“规则未命中”，必须进入一次受限 LLM 意图识别；LLM 仍无法产生有效变化时才澄清。意图请求只附带
当前风险偏好和冲/稳/保数量摘要，不发送候选身份。

“冲的比例太少，增加多几个”在没有具体数量时映射为 `risk_appetite=aggressive`，由确定性
算法使用固定配比，不允许模型自行计算数量或比例。首次生成允许在目标档候选不足时发布
最接近可行方案并明确告警；已有报告后的明确增档修订必须让目标档数量实际增加，否则以
`TARGET_ALLOCATION_UNSATISFIED` 失败并保留旧报告。

明确“增加冲档”表达由确定性规则直接识别并写入 `allocation_request=MORE_RUSH`，
不能依赖风险偏好字段是否发生变化，也不能因为其他画像字段被归一化而绕过目标档门禁。
只有含义不明确的胆量或偏好表达才交给 LLM 兜底。前端恢复画像时空列表必须保持为空，
不能用界面默认城市替代服务端已确认的画像。
