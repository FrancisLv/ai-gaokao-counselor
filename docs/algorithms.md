# 志愿算法设计：位次 → 概率 → 冲稳保 → 志愿表

> svc-algo 使用历史数据生成粗粒度风险分档，按偏好选择并排序志愿。当前覆盖湖南新高考 3+1+2 本科批；概率不是经校准的真实录取概率，更不构成录取保证。
>
> 原则：**全部确定性、可复现、可审计**——数值由算法给，人话解释由 LLM 写。
>
> 📌 **本文定位**：只讲**算法设计理念（为什么这么算）**，是通俗版。**实现细节、数据结构、最新参数默认值、代码模块划分与函数签名，一律以 [`task2-implementation-plan.md`](./task2-implementation-plan.md) 为准**——本文刻意不重复这些易变内容，避免两份文档漂移。

---

## 0. 总览：四步流水线

```
① 翻译你的分数        ② 算每个学校的录取概率     ③ 打"心动分"       ④ 挑出最优志愿组合
  分数→排名→百分位   →  看历史数据算概率       →  看你的偏好打分  →  冲稳保搭配 + 排序
                                                          ↑
                                               ⑤ 保底检查：够不够稳、会不会滑档？
```

**关键直觉**：每年题目难度和人数不同，以同省、同科类的位次占总人数比例作跨年近似比较，比直接比较分数更合理；仍不能消除招生政策与考生偏好变化。

## 1. 先认识几个概念

别被符号吓到，每个概念都有大白话解释：

| 符号 | 大白话 | 举例 |
|------|--------|------|
| `r_u` | 你在全省排第几名（位次） | 你排第 2000 名 |
| `T` | 全省一共有多少人参加考试 | 今年 10 万人 |
| `q_u` | 位次占同科类总人数的比例，越小越靠前 | 2000/100000 = 0.02（前约 2%） |
| `g` | 一个院校专业组（并非一个具体专业） | 招生代码＋专业组代码 |
| `R_i` | 组内专业最低位次的最小值，当前模型的组线代理 | `MIN(min_rank)`，不等同官方组投档线 |
| `q_i` | 组线代理位次占当年同科类总人数的比例 | 1800/100000 = 0.018 |
| `P_j` | 你被这个学校录取的概率 | 70% |
| `U_j` | 你对这个学校的"心动程度"（0~1） | 0.9 = 非常想去 |
| `L` | 服务配置的志愿表数量上限 | 当前按湖南本科场景配置，具体值见实现文档 |

**历史命中的判定逻辑**：用户百分位 ≤ 历史组线百分位，记为该历史样本命中。例如 0.02 ≤ 0.03 表示历史上够得着，不表示今年一定录取或能进入组内任意专业。

## 2. 第一步：把你的分数"翻译"成年年能比的数字（`rank`）

### 为什么不能直接比分数？

| 年份 | 数学难度 | 你的分数 | 全省排名 | 超过了 |
|------|----------|----------|----------|--------|
| 2024 | 难 | 580 | 第 3000 名 | 97% |
| 2025 | 简单 | 580 | 第 8000 名 | 92% |

同样是 580 分，含金量完全不同。**所以我们要用"百分位"而不是"分数"。**

### 怎么做？

1. **分数→位次**：查"一分一段表"，看你的分数排第几名
2. **位次→百分位**：用 `你的排名 ÷ 同省同科类总人数`，分母取该年一分一段表跨批次最大累计人数

> 例：你排 2000 名，全省 10 万人 → 百分位 = 2000/100000 = 0.02（越小越好，说明你很靠前）

### 为什么不用"线差法"（分数减去批次线）？

因为批次线本身也在变，而且有些省份合并了本科批次，线差法直接失效。**百分位最稳定。**

---

## 3. 第二步：算你被每个学校录取的概率（`prob`）

### 思路很简单

只使用报考年之前的历史窗口；以报考 2025 年为例，用 2022–2024 年，不使用 2025 年录取结果：

```
年份     学校录取百分位    你的百分位    够不够？
2022     0.018            0.02         ❌ 差一点
2023     0.022            0.02         ✅ 够
2024     0.020            0.02         ✅ 刚好

→ 3 个样本中 2 个命中；实际按时效权重计算，不直接以 2/3 分档
```

### 但实际算法更精细一些

**① 越近的年份越有参考价值（时效加权）**

历史记录按年降序排列，以记录下标作衰减指数。缺年份时不按自然年份差额外衰减，这是当前模型的简化；参数与公式见实现文档 §3.2。

**② 招生人数变了也要调整**

如果某校今年扩招了 20%，那录取线大概率会降低（更容易进）。算法会把这个因素考虑进去。

**③ 统一用加权命中率法（透明，但小样本不确定性大）**

| 有效数据量 | 用什么方法 | 大白话 |
|-----------|-----------|--------|
| ≥1 年 | 加权命中率 | 历史上"够得着"的年份占多大比例（近年权重更高） |
| 0 年 | **不推荐** | 没数据就没法算，直接不推荐 |

> 为什么不用正态分布 / 核密度估计？只有 3 年数据，样本太少估不准分布，反而误导；加权命中率简单透明，但不能凭少量样本证明可靠性。（数据积累到 5 年以上后，可再考虑升级为核密度估计等。）

### 输出结果

每个学校会给你：
- **录取概率**：1%~99%（避免绝对 0/100）
- **依据**：用了几年的数据、哪种方法
- **分档**：冲 / 稳 / 保（见下一步）

> **铁律**：没数据就直接不推荐（概率记为极低值后被过滤），**绝不编造概率**。
> 注：概率是粗粒度、供分档用的；"依据不足""数据较少"等提示由前端根据数据年数展示，后端只给客观数值。

## 4. 第三步：给每个学校打"心动分"（效用 U_j）

概率告诉你"能不能上"，但你还要考虑"想不想去"。

### 打分维度

| 维度 | 问的是什么 | 数据来源 |
|------|-----------|----------|
| 学校层次 | 是 985/211/双一流吗？ | 院校库 |
| 专业匹配 | 组里有没有你想学的方向？ | 你的画像 + 专业库 |
| 地域匹配 | 在你想去的城市吗？不在的话是不是同省？ | 你的画像 + 院校位置 |
| 学校实力 | 硕博点多不多、排名高不高？ | 院校库 |

> 几个"为什么这么设计"：
> - **专业匹配用关键词包含**（你说的兴趣方向能对上专业名就算命中），简单、透明、可解释。更聪明的语义匹配需要调大模型，会让打分变慢、变得不可复现，留作后续优化。
> - **地域只分三档**（想去的城市 / 同省 / 其他），不搞"相邻省加分"——因为库里没有省份邻接关系数据，与其硬造一张配置表，不如简单三档（YAGNI）。
> - **风险偏好（冲还是求稳）不在心动分里**——它影响的是第四步冲稳保的配比，保底数量独立由配置决定，不该和"想不想去"混在一起。
> - **你说"想去 985/211"是软偏好、不是硬门槛**——系统会提高"学校层次"这一维的权重，让符合你层次的学校排更前，但不会把其他学校直接踢出候选。万一你分数够不上偏好层次，仍有其他学校可兜底。

### 怎么算？

每个维度有个权重（你最看重什么，权重就高），最后加权求和：

```
心动分 = 学校层次得分 × 权重 + 专业匹配得分 × 权重 + 地域得分 × 权重 + 学校实力得分 × 权重
```

> algo 根据传入画像的优先维度调整并归一化权重。由 LLM 提取画像是目标架构，上游完整对话链尚未完成。
> 但**打分公式是固定的**——LLM 只负责理解你的意思，不负责算分。

## 5. 第四步：冲稳保分档

按录取概率自动分类：

| 分档 | 概率范围 | 什么意思 | 填志愿时的心态 |
|------|----------|----------|---------------|
| **冲** | 冲阈值至稳阈值（不含上界） | 历史命中较少 | 相对高风险 |
| **稳** | 稳阈值至保阈值（不含上界） | 历史命中较多 | 相对中风险 |
| **保** | 不低于保阈值 | 历史命中更多 | 仍有风险，不保证录取 |

> 低于冲阈值不推荐。具体阈值见实现文档；最终排序按效用，不强制按分档顺序。

---

## 6. 第五步：帮你挑出最优志愿组合（`optimize`）

### 平行志愿的规则（必须先懂这个）

> **"分数优先，遵循志愿"**：系统按排名从高到低处理，轮到你时，按你填的顺序 1→2→3... 依次看，**投进第一个还有名额的学校，后面全部作废。**

这意味着：
- 排在前面的志愿优先级最高
- 一旦被录取，后面的志愿就不看了
- 如果所有志愿都没名额 → **滑档**（没学上了）

### 排序规则

**把效用最高的排前面。** 并列时按招生代码、专业组代码升序，保证可复现；该偏好排序不等于真实录取过程的全局最优解。

### 选哪些学校进来？

真正的难题不是排序，而是**从几百个候选里挑出哪 L 个**。

策略：
1. 按风险偏好确定各档配额，各档内按效用取优。
2. 某档不足时，用剩余候选按全局效用补空位。
3. 保底检查在总数上限内补入或替换，再按全序规则排序。当前未实现局部搜索。

### 必须满足的硬约束

| 约束 | 说明 |
|------|------|
| 总数 ≤ L | 保底补齐也不能突破配置上限 |
| 组主键唯一 | 重复组、非法概率、未知分档不能进入优化 |
| 选科与范围 | 校验湖南本科场景及 3+1+2 选科；未实现体检过滤 |
| 保底目标 | 优先满足配置的稳拿数量；池不足则返回成功告警 |

### 尽量满足的软约束

| 约束 | 说明 |
|------|------|
| 冲稳保比例 | 由风险偏好决定，候选不足或补保底时可偏离 |
| 效用优先 | 最终全表按效用排序，不强制概率递增 |

---

## 7. 第六步：保底检查（`optimize`）

填好志愿表后，统计更高阈值下的保底数量；“稳拿”仅为模型标签：

```
① 数一数概率达到稳拿阈值的组
   → 不足配置目标时，从未入选稳拿池取候选；有空位补入，满额则替换最低效用非稳拿项

② 滑档率直接用公式算（不用模拟）：
   滑档率 = (1-p₁) × (1-p₂) × … × (1-pₙ)
   → 假设各组录取事件独立；现实中高度相关，数值小不代表真实风险小

③ 期望满意度 = 志愿表里各学校心动分的平均
```

> 乘积只是简化风险指标，未建模相关性、政策变化、退档或专业调剂。`ExpectedSatisfaction` 实际是平均效用，并非录取概率加权期望。保底不足通过 `SafeGuardOK=false` 告警，不返回 RPC 错误。

## 9. 遇到特殊情况怎么办？

| 情况 | 处理方式 |
|------|----------|
| 某个学校完全没有历史数据 | 不推荐（概率记极低值被过滤）；"依据不足"提示由前端展示 |
| 只有 1 年数据 | 数据年数少、可信度低（前端可据 DataYears 标注"高风险"） |
| 新高考第一年 / 批次合并 | 当前没有自动政策可比性校正，需人工核对适用性 |
| 某校今年突然大幅扩招/缩招 | 用计划修正因子调整；数据波动大，前端可提示"仅供参考" |
| 找不到足够的"保底"学校 | 建议放宽地域或专业偏好，或直接告知"保底不足" |

## 10. 资格规则与覆盖声明

资格不是概率模型的一部分，而是候选进入优化的硬门禁。`EvaluateEligibility` 在固定
`release_id` 内读取 PUBLISHED 规则和覆盖声明：规则 TRUE 表示明确限报，FALSE 表示
该规则未命中，无法求值则为 UNKNOWN。任何 UNKNOWN 都不能被解释为通过。

覆盖声明按 `rule_type + scope` 独立发布。同一专业的适用声明取 scope 最具体者：
专业级优先于组级、院校级和省级；同具体度出现多个不同声明时无法得到唯一事实，
整体结果阻断。FULL 才允许专业 PASS，PARTIAL、NONE 或没有声明都保持 UNKNOWN。
覆盖在 release 发布后冻结，因此同一 run 不会因后续配置修改得到另一套结果。

## 11. 检索 golden set 指标口径

检索评测只通过 `RetrievePolicy` 的公开结果计算，不读取 SQL 行、向量距离或 rerank
模型私有结构。

- `recall@k = 至少命中一条 expected chunk/doc 的有效 Case 数 / 有效 Case 数`；
- `expected` 命中要求最终 `EvidenceRef` 的 `chunk_id` 或 `doc_id` 在标注集合内，
  相同关键词但非预期证据不计命中；
- 普通 Case 未命中进入分母并计 0；只有明确 `NO_EVIDENCE` 的 Case 走独立状态验收，
  不进入 recall/MRR 分母；
- `MRR = mean(1 / 首次命中排名)`，未命中计 0；
- `evidence_precision@5 = top-5 中 acceptable chunk 数 / 实际返回的 top-5 证据数`；
  `irrelevant_evidence_rate = 1 - evidence_precision@5`；
- MRR 阈值只在真实 `RetrievePolicy` 且 `owner_status=SIGNED_OFF` 的权威质量门禁中
  与 recall@5 一起参与判定；草稿/fixture 仍记录 MRR，但不把未签字数据变成发布门禁；
- `must_exclude_chunk_ids` 命中产生逐例 hard-negative leak；它用于检测同一文档内
  的低相关补位证据，不能被文档级 recall 掩盖；
- 每条返回证据都检查 release、文档类型、省、年、科类、批次、学校身份与
  `must_exclude_sources`。任一越界都
  产生逐例 leak，`scope_leak_rate > 0` 直接使门禁失败，不能用平均 recall 抵消；
- 跨省/跨年/跨科类/错误学校 Case 必须携带结构化 `interference` 元数据，供 harness
  独立构造干扰证据并验证 leak，而不是只依赖标签；
- 失败 Case 保存实际证据和 first diff；baseline 同时记录 dataset hash、release、
  代码身份、embedding、rerank、RRF、index version、运行环境与 `as_of`。

`rerank_enabled=false` 是当前可执行基线。rerank 字段保留在报告中，但真实 rerank
模型质量不在本阶段验收范围。确定性 fixture 基线只验证评测链路，其
`authoritative_quality=false`，不得作为检索质量结论；真实检索也只有在
`owner_status=SIGNED_OFF` 时才标记为权威质量结果。
