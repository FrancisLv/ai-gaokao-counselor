# 兰州大学（110）专业组错误进入保档复盘

- 日期：2026-11-21
- 状态：已修复并完成真实链路回归
- 影响范围：湖南 2025 物理类推荐概率、冲稳保分档、跨年专业组 lineage
- 原问题报告：`dc44f88d-f630-4f8d-85b8-3bc3a7a8b4ff`
- 修复后验收报告：`341901c7-1d5c-4f62-a811-a28a60684320`

## 1. 用户现象

兰州大学（110）专业组只有 2024 年历史记录：

- 2024 年最低位次：11,375
- 2025 年用户位次：15,860
- 页面结果：录取概率 99%，进入“保”档

用户位次数值更大，表示排名更靠后。按历史最低位次直接比较，用户没有达到
2024 年组线，却得到最高概率，属于明显异常。

## 2. 数据证据

专业组代码在两年之间被学校复用，但组内专业完全不同：

| 年份 | 兰州大学（110）组内专业 | 计划数 |
| --- | --- | ---: |
| 2024 | 临床医学、口腔医学、预防医学、药学 | 23 |
| 2025 | 数学、物理、计算机、电子信息等 23 个理工专业 | 79 |

两年的专业名称集合 Jaccard 重合度为 `0`。与 2025 年（110）最相近的是 2024 年
（109）组，但重合度也只有 `12 / 26 = 46.15%`，低于可靠映射阈值 60%。

## 3. 根因链

### 3.1 同代码被错误视为同身份

`group-lineage-v1` 在发现同院校、同专业组代码时，直接记录：

- `mapping_method = EXACT_CODE`
- `confidence = 1`

该分支没有要求专业构成重合。代码只是当年的招生编号，学校可以跨年复用，因此不能用
代码相同证明组内专业相同。

问题位于 `scripts/build_group_lineage.py` 的旧精确代码分支。

### 3.2 错误历史数据被计划修正进一步放大

系统随后使用 2024 计划 23 人、2025 计划 79 人计算修正倍率：

```text
计划变化率 = (79 - 23) / 23 = 2.4348
修正倍率 = 1 + 2.4348 × 0.5 = 2.2174
```

历史组线百分位因此从：

```text
11375 / 313685 = 3.6262%
```

被放大到：

```text
3.6262% × 2.2174 = 8.0408%
```

用户百分位为：

```text
15860 / 320192 = 4.9533%
```

由于 `4.9533% <= 8.0408%`，唯一一年被判定为“命中”。

### 3.3 单年样本被输出为极端概率

旧版加权命中率在只有一年且命中时直接输出 `99%`，没有反映单年样本的不确定性，
最终触发“保”档阈值。

## 4. 排除项

以下环节经数据核对不是本次根因：

- 用户位次和百分位换算正确。
- 2024 年最低分 608、最低位次 11,375 取数正确。
- 99% 落入“保”档阈值后分类正确。
- 问题发生在概率分类之前的跨年身份匹配和历史样本修正。

## 5. 修复方案

### 5.1 lineage v2

- 映射升级为 `group-lineage-v2`。
- 同院校、同首选科目且专业名称 Jaccard 达到 60% 才允许成为候选映射。
- 专业组代码相同只在最高重合度并列时作为 tie-break。
- 低重合或不唯一时不建立映射；无可靠历史的组不进入冲稳保正式列表。

### 5.2 概率校准

- 3 年历史：最高 99%。
- 2 年历史：最高 95%。
- 1 年历史：最高 75%，不能单独形成保底结论。
- 计划修正倍率限制在 `0.5–1.5`。
- 修正后的历史组线百分位封顶 100%。

### 5.3 数据重建

隔离验收库重建后：

| 科类 | 目标组 | 可靠映射组 | 完整三年组 |
| --- | ---: | ---: | ---: |
| 物理类 | 3,848 | 2,380 | 245 |
| 历史类 | 1,816 | 1,190 | 201 |

物理类可靠映射组从 v1 的 3,069 降至 2,380，是移除错误精确匹配后的预期结果。

## 6. 回归验证

- 兰州大学 2025（110）到 2024（110）的错误映射数：`0`
- 修复后 600 分物理类报告：冲 10 / 稳 22 / 保 13
- 兰州大学（110）在最终报告中出现次数：`0`
- 最终报告状态：`SUCCEEDED`

测试覆盖：

- Python lineage 纯函数测试：同代码零重合拒绝、复用代码转向高重合组、同代码高重合
  保留、歧义候选拒绝。
- Go 测试：单年/两年概率上限、计划修正倍率封顶、历史审计不被计划修正污染。
- 完整 Go 检查与测试。
- 真实 PostgreSQL Algo 集成测试。
- 完整真实 Gateway Playwright 4 项。

## 7. 复盘结论

- 院校专业组代码不是稳定的跨年主键，不能单独作为高置信身份。
- 历史数据缺失比套用错误历史更安全；无可靠映射时不得推荐。
- 少样本概率必须表达不确定性，不能把单年命中直接当作 99%。
- 数据发布时需要同时看“映射数量”和“映射质量”，覆盖率下降不一定是回归。
